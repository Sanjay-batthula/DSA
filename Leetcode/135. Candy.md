# 135. Candy

## Problem Statement
Each child must receive at least one candy, and any child with a higher rating than a neighbor must receive more candies than that neighbor. The goal is to distribute the minimum total number of candies that satisfies these conditions.

## Sample Test Cases
| Input | Output |
| --- | --- |
| `ratings = [1,0,2]` | `5` |
| `ratings = [1,2,2]` | `4` |

## Constraints
- `n == ratings.length`
- `1 <= n <= 2 * 10^4`
- `0 <= ratings[i] <= 2 * 10^4`

## Approaches
| Approach | Pattern | Time Complexity | Space Complexity |
| --- | --- | --- | --- |
| Two-pass greedy with left/right arrays | Greedy / Array DP | `O(n)` | `O(n)` |
| Slope tracking | Greedy | `O(n)` | `O(1)` |

## Code
### Pattern
- Greedy
- Array-Based DP

### Intuition
The constraints are local: each child only needs to compare with the immediate left and right neighbors. A natural greedy strategy is to satisfy the left rule first and then the right rule. The left pass ensures that increasing ratings receive more candies than the previous child. The right pass fixes violations from the right side by taking the maximum of the left-based and right-based assignments.

The slope-tracking solution compresses the same idea into one pass. It handles increasing, flat, and decreasing slopes while maintaining the number of candies needed for the current descending run.

### Algorithm
1. Initialize `left[i] = 1` and `right[i] = 1` for all children.
2. Scan from left to right and increase `left[i]` if `ratings[i] > ratings[i - 1]`.
3. Scan from right to left and increase `right[i]` if `ratings[i] > ratings[i + 1]`.
4. Sum `max(left[i], right[i])` for all `i`.

### Code
```java
class Solution {
    public int candy(int[] ratings) {
        int n = ratings.length;
        int[] left = new int[n];
        int[] right = new int[n];
        Arrays.fill(left, 1);
        Arrays.fill(right, 1);

        for (int i = 1; i < n; ++i) {
            if (ratings[i] > ratings[i - 1]) {
                left[i] = left[i - 1] + 1;
            }
        }

        for (int i = n - 2; i >= 0; --i) {
            if (ratings[i] > ratings[i + 1]) {
                right[i] = right[i + 1] + 1;
            }
        }

        int ans = 0;
        for (int i = 0; i < n; ++i) {
            ans += Math.max(left[i], right[i]);
        }
        return ans;
    }
}
```

### Complexity
- Time Complexity: `O(n)`
- Space Complexity: `O(n)`

## Other Approaches
### Greedy Slope Tracking
#### Pattern
- Greedy
- Single Pass

#### Intuition
This method avoids storing both arrays by tracking the current slope of the ratings. When the ratings are increasing, we add candies for the ascent. When the ratings are decreasing, we account for the descent and adjust for the peak. The peak value helps avoid undercounting when a descending run follows an increasing run.

#### Algorithm
1. Initialize `candies = 1`, `up = 0`, `down = 0`, and `peak = 0`.
2. For each adjacent pair:
   - If ratings increase, extend the increasing slope.
   - If ratings are equal, reset the slope counters.
   - If ratings decrease, extend the descending slope and adjust the candy count.
3. Return the total candies.

#### Code
```java
class Solution {
    public int candy(int[] ratings) {
        int n = ratings.length;
        int candies = 1;
        int up = 0;
        int down = 0;
        int peak = 0;

        for (int i = 1; i < n; i++) {
            if (ratings[i] > ratings[i - 1]) {
                up++;
                peak = up;
                down = 0;
                candies += 1 + up;
            } else if (ratings[i] == ratings[i - 1]) {
                up = 0;
                down = 0;
                peak = 0;
                candies += 1;
            } else {
                up = 0;
                down++;
                candies += 1 + down - (peak >= down ? 1 : 0);
            }
        }
        return candies;
    }
}
```

#### Complexity
- Time Complexity: `O(n)`
- Space Complexity: `O(1)`

## Approach Comparison
| Approach | Pattern | Time | Space | Pros | Cons |
| --- | --- | --- | --- | --- | --- |
| Two-pass greedy | Greedy / Array DP | `O(n)` | `O(n)` | Easy to reason about and implement | Uses extra arrays |
| Slope tracking | Greedy | `O(n)` | `O(1)` | Constant extra space | Slightly more subtle to understand |

## Key Observations
- The problem is local and can be solved greedily.
- Each child must satisfy both left and right constraints, so the final answer is the maximum of the two contributions.
- Descending runs require special handling because the peak child must be counted correctly.

## Common Mistakes
- Forgetting that each child must receive at least one candy.
- Not accounting for the peak when a descending run follows an increasing run.
- Using only one directional pass and missing the opposite constraint.

## Related Patterns
- Greedy
- Array Traversal
- Two-Pass Scanning

## Summary
- The optimal solution uses a greedy strategy to satisfy the left and right constraints.
- The pattern is greedy with local comparisons.
- Time complexity is `O(n)`, and the two-pass version uses `O(n)` extra space while the slope-tracking version uses `O(1)` space.
- Interview takeaway: when constraints are local and directional, greedy solutions often work well if you model both sides carefully.
