
# 136. Single Number

## Problem Statement

Given a non-empty array of integers $\text{nums}$, every element appears twice except for one. Find that single one.

You must implement a solution with a linear runtime complexity and use only constant extra space.

---

## Sample Test Cases

| Input | Output | Explanation |
|-------|--------|-------------|
| nums = [2,2,1] | 1 | 1 appears only once |
| nums = [4,1,2,1,2] | 4 | 4 appears only once |
| nums = [1] | 1 | 1 appears only once |

---

## Constraints

- $1 \leq \text{nums.length} \leq 3 \times 10^4$
- $-3 \times 10^4 \leq \text{nums}[i] \leq 3 \times 10^4$
- Each element in the array appears twice except for one element which appears only once

---

## Approaches

| Intuition | Approach | Time Complexity | Space Complexity |
|-----------|----------|-----------------|-----------------|
| Brute Force | Count occurrences | $O(n^2)$ | $O(1)$ |
| Bit Manipulation | XOR all elements | $O(n)$ | $O(1)$ |

---

## Code: Brute Force

```java
class Solution {
    public int singleNumber(int[] nums) {
        for (int i = 0; i < nums.length; i++) {
            int count = 0;
            for (int j = 0; j < nums.length; j++) {
                if (nums[i] == nums[j]) count++;
            }
            if (count == 1) return nums[i];
        }
        return -1;
    }
}
```

---

## Code: Bit Manipulation (XOR)

```java
class Solution {
    public int singleNumber(int[] nums) {
        int ans = 0;
        for (int v : nums) {
            ans ^= v;
        }
        return ans;
    }
}
```

---

## Approach Comparison

| Approach | Time Complexity | Space Complexity | Notes |
|----------|-----------------|-----------------|-------|
| Brute Force | $O(n^2)$ | $O(1)$ | Slow, not optimal |
| Bit Manipulation | $O(n)$ | $O(1)$ | Efficient, uses XOR |

---

## Summary

- XOR approach is optimal and uses constant space.
- Brute force is slow and not recommended.
