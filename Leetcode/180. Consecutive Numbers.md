# 180. Consecutive Numbers

## Problem Statement
Find all numbers that appear at least three times consecutively in the Logs table. Return the distinct numbers that satisfy this condition.

## Table Schema
| Column | Type | Description |
| --- | --- | --- |
| id | int | Primary key, auto-incremented |
| num | varchar | Number value in the log |

## Sample Data
### Logs
| id | num |
| --- | --- |
| 1 | 1 |
| 2 | 1 |
| 3 | 1 |
| 4 | 2 |
| 5 | 1 |
| 6 | 2 |
| 7 | 2 |

### Expected Output
| ConsecutiveNums |
| --- |
| 1 |

## SQL Pattern
- SELECT
- DISTINCT
- JOIN
- SELF JOIN
- Window Functions
- LAG
- ORDER BY

Alternative patterns:
- Self Join with multiple joins
- Window Function with lag comparisons

## Solution 1 (Recommended)

### Technique
Window Function with LAG

### Why it Works
The query compares each row with the previous one and the row before that. If all three values are the same, then the current number appears consecutively at least three times.

### Query
```sql
SELECT DISTINCT num AS ConsecutiveNums
FROM (
    SELECT 
        num,
        LAG(num, 1) OVER (ORDER BY id) AS prev1,
        LAG(num, 2) OVER (ORDER BY id) AS prev2
    FROM Logs
) t
WHERE num = prev1 AND num = prev2;
```

### Query Breakdown
- SELECT: chooses the final output column.
- LAG(num, 1): gets the previous row's number.
- LAG(num, 2): gets the number from two rows earlier.
- OVER (ORDER BY id): orders rows by their id to evaluate consecutive positions.
- WHERE: keeps rows where the current number matches both previous values.
- DISTINCT: removes duplicates if several rows satisfy the condition.

### Complexity
- Time Complexity: `O(n)`
- Space Complexity: `O(n)`

## Other Solutions

### Solution 2

### Technique
Self Join

### Why it Works
A self join connects each row with the previous and previous-previous rows. If all three rows share the same number, the middle row satisfies the condition.

### Query
```sql
SELECT DISTINCT l1.num AS ConsecutiveNums
FROM Logs l1
JOIN Logs l2
  ON l1.id = l2.id - 1 AND l1.num = l2.num
JOIN Logs l3
  ON l2.id = l3.id - 1 AND l2.num = l3.num;
```

### Complexity
- Time Complexity: `O(n)`
- Space Complexity: `O(n)`

## Solution Comparison
| Technique | SQL Features | Readability | Performance | Best Use Case |
| --- | --- | --- | --- | --- |
| Window Function | LAG, OVER | High | Good | Clean and modern approach |
| Self Join | JOIN, SELF JOIN | Moderate | Good | Useful when window functions are unavailable |

## Pattern Recognition
This pattern should come to mind when the problem asks for:
- consecutive rows with the same value
- repeated values in sequence
- streaks or runs in ordered data

## Common Mistakes
- Forgetting to order by `id` when checking consecutive rows.
- Using the wrong join condition for consecutive rows.
- Missing `DISTINCT` when the same number appears in multiple qualifying groups.

## Interview Tips
- Mention that the problem is about a streak of identical values in ordered rows.
- If asked, explain why the window function version is often the clearest.

## Revision Summary
- Main SQL pattern: consecutive-row comparison using window functions
- Best solution: use `LAG` to compare current row with previous rows
- Alternative technique: self join for consecutive rows
- Common pitfalls: incorrect ordering and missing distinct values
- Key takeaway: the answer is the number that appears in a run of length at least three
