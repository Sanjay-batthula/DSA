# 196. Delete Duplicate Emails

## Problem Statement
Delete all duplicate emails from the Person table while keeping only the row with the smallest id for each email.

## Table Schema
| Column | Type | Description |
| --- | --- | --- |
| id | int | Primary key |
| email | varchar | Email address |

## Sample Data
### Person
| id | email |
| --- | --- |
| 1 | john@example.com |
| 2 | bob@example.com |
| 3 | john@example.com |

### Expected Output
| id | email |
| --- | --- |
| 1 | john@example.com |
| 2 | bob@example.com |

## SQL Pattern
- DELETE
- JOIN
- GROUP BY
- MIN
- IN
- Subquery

Alternative patterns:
- Self Join delete
- Grouped minimum-id deletion

## Solution 1 (Recommended)

### Technique
Self Join Delete

### Why it Works
If two rows share the same email and one has a larger id, that row is a duplicate and should be removed. The join compares each row with all other rows that have the same email and a smaller id.

### Query
```sql
DELETE p1
FROM Person p1
JOIN Person p2
  ON p1.email = p2.email AND p1.id > p2.id;
```

### Query Breakdown
- DELETE p1: removes the duplicate row from the first table reference.
- JOIN Person p2: compares each row to every other row with the same email.
- ON p1.email = p2.email AND p1.id > p2.id: keeps only rows whose id is larger than another row with the same email.

### Complexity
- Time Complexity: `O(n^2)` in the worst case
- Space Complexity: `O(1)`

## Other Solutions

### Solution 2

### Technique
Grouped Minimum-ID Deletion

### Why it Works
For each email, the smallest id is the one that must survive. All rows whose id is not one of these minimum ids are duplicates and can be deleted.

### Query
```sql
DELETE FROM Person
WHERE id NOT IN (
    SELECT id
    FROM (
        SELECT MIN(id) AS id
        FROM Person
        GROUP BY email
    ) t
);
```

### Complexity
- Time Complexity: `O(n)` to group and compare ids
- Space Complexity: `O(n)`

## Solution Comparison
| Technique | SQL Features | Readability | Performance | Best Use Case |
| --- | --- | --- | --- | --- |
| Self Join Delete | DELETE, JOIN | High | Good | Straightforward duplicate removal |
| Grouped Minimum-ID Deletion | GROUP BY, MIN, IN, subquery | Moderate | Good | Explicitly identifies surviving ids |

## Pattern Recognition
This pattern should come to mind when the problem asks for:
- delete duplicates while keeping the earliest record
- keep one row per group based on a minimum or maximum value
- deduplicate data with a primary key

## Common Mistakes
- Deleting the wrong row when ids are not compared correctly.
- Forgetting that only the minimum id per email should remain.
- Using `=` instead of `>` in the self-join condition.

## Related SQL Concepts

## Interview Tips
- Mention that the solution should preserve the smallest id for each email.
- If asked, explain that a self-join is often the most direct delete solution.
- Be careful with MySQL delete behavior when using subqueries.

## Revision Summary
- Main SQL pattern: delete duplicates by comparing ids within the same email group
- Best solution: self-join to remove rows with a larger id for the same email
- Alternative technique: derive the minimum id per email and delete the rest
- Common pitfalls: incorrect id comparison and duplicate-preserving logic
- Key takeaway: keep exactly one row per email, using the smallest id
