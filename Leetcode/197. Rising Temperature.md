# 197. Rising Temperature

## Problem Statement
Find all ids where the temperature is higher than the temperature on the previous day. The comparison is based on consecutive dates.

## Table Schema
| Column | Type | Description |
| --- | --- | --- |
| id | int | Primary key |
| recordDate | date | Date of the record |
| temperature | int | Temperature value |

## Sample Data
### Weather
| id | recordDate | temperature |
| --- | --- | --- |
| 1 | 2015-01-01 | 10 |
| 2 | 2015-01-02 | 25 |
| 3 | 2015-01-03 | 20 |
| 4 | 2015-01-04 | 30 |

### Expected Output
| id |
| --- |
| 2 |
| 4 |

## SQL Pattern
- SELECT
- WHERE
- DATE Functions
- Self Join
- Window Functions
- LAG

Alternative patterns:
- Scalar subquery with date subtraction
- Self join with date difference

## Solution 1 (Recommended)

### Technique
Self Join with Date Comparison

### Why it Works
Each row is compared with the row from the previous day. If the current temperature is greater and the dates differ by exactly one day, the row qualifies.

### Query
```sql
SELECT w1.id
FROM Weather AS w1
JOIN Weather AS w2
  ON DATEDIFF(w1.recordDate, w2.recordDate) = 1
 AND w1.temperature > w2.temperature;
```

### Query Breakdown
- SELECT w1.id: returns the id of the current day.
- JOIN Weather AS w2: compares the current row with another row from the table.
- DATEDIFF(w1.recordDate, w2.recordDate) = 1: ensures the compared row is from the previous day.
- w1.temperature > w2.temperature: checks that the temperature increased.

### Complexity
- Time Complexity: `O(n)`
- Space Complexity: `O(1)`

## Other Solutions

### Solution 2

### Technique
Scalar Subquery

### Why it Works
For each row, the subquery looks up the temperature from the previous day and compares it directly.

### Query
```sql
SELECT id
FROM Weather w1
WHERE temperature > (
    SELECT temperature
    FROM Weather w2
    WHERE w2.recordDate = DATE_SUB(w1.recordDate, INTERVAL 1 DAY)
);
```

### Complexity
- Time Complexity: `O(n)`
- Space Complexity: `O(1)`

### Solution 3

### Technique
Window Function with LAG

### Why it Works
The previous day’s temperature can be accessed directly using a window function over the ordered dates.

### Query
```sql
SELECT id
FROM (
    SELECT id,
           temperature,
           LAG(temperature) OVER (ORDER BY recordDate) AS prev_temp
    FROM Weather
) t
WHERE temperature > prev_temp;
```

### Complexity
- Time Complexity: `O(n)`
- Space Complexity: `O(n)`

## Solution Comparison
| Technique | SQL Features | Readability | Performance | Best Use Case |
| --- | --- | --- | --- | --- |
| Self Join | JOIN, DATEDIFF | High | Good | Most direct and intuitive |
| Scalar Subquery | Subquery, DATE_SUB | High | Good | Useful when comparing one row to another explicitly |
| Window Function | LAG, OVER | Moderate | Good | Clean for ordered time-series comparisons |

## Pattern Recognition
This pattern should come to mind when the problem asks for:
- day-to-day change comparison
- previous row comparison in ordered data
- temperature or value increase over time

## Common Mistakes
- Comparing dates incorrectly and missing the previous day relation.
- Forgetting to use the date difference condition in the self join.
- Using the wrong date function for the database engine.

## Related SQL Concepts
- Date Functions
- Self Join
- Window Functions
- LAG
- Subqueries

## Interview Tips
- Mention that the comparison is between consecutive dates, not arbitrary dates.
- If asked, note that window functions are elegant for ordered time-series problems.
- Be mindful of database-specific date functions like `DATEDIFF` or `DATE_SUB`.

## Revision Summary
- Main SQL pattern: compare each row with the previous day’s row
- Best solution: self join on a one-day date difference
- Alternative techniques: scalar subquery and LAG-based window function
- Common pitfalls: incorrect date comparison and missing previous-day check
- Key takeaway: return rows whose temperature rises from the prior day
