# 215. Kth Largest Element in an Array

## Problem Statement
Given an integer array and an integer k, find the kth largest element in the array. The answer is based on the sorted order, not the kth distinct element.

## Sample Test Cases
| Input | Output |
| --- | --- |
| `nums = [3,2,1,5,6,4], k = 2` | `5` |
| `nums = [3,2,3,1,2,4,5,5,6], k = 4` | `4` |

## Constraints
- `1 <= k <= nums.length <= 10^5`
- `-10^4 <= nums[i] <= 10^4`

## Approaches
| Approach | Pattern | Time Complexity | Space Complexity |
| --- | --- | --- | --- |
| Min heap | Heap / Priority Queue | `O(n log k)` | `O(k)` |
| Quickselect | Divide and Conquer / Partitioning | `O(n)` average | `O(1)` |
| Sorting | Sorting | `O(n log n)` | `O(1)` or `O(n)` |

## Code
### Pattern
- Heap
- Priority Queue

### Intuition
To find the kth largest element, we only need to track the top k largest values. A min-heap keeps the smallest element among the current top candidates at the root, so when the heap grows beyond size k, we discard the smallest value. At the end, the heap root is the kth largest element.

### Algorithm
1. Create a min-heap.
2. Traverse the array.
3. Insert each value into the heap.
4. If the heap size exceeds `k`, remove the smallest value.
5. After processing all elements, the heap root is the kth largest element.

### Code
```java
class Solution {
    public int findKthLargest(int[] nums, int k) {
        PriorityQueue<Integer> pq = new PriorityQueue<>();

        for (int num : nums) {
            pq.offer(num);
            if (pq.size() > k) {
                pq.poll();
            }
        }
        return pq.peek();
    }
}
```

### Complexity
- Time Complexity: `O(n log k)`
- Space Complexity: `O(k)`

## Other Approaches
### Quickselect
#### Pattern
- Divide and Conquer
- Partitioning

#### Intuition
Quickselect works like quicksort but only recurses into the partition that contains the target position. It rearranges elements so that the kth largest element ends up at the correct index.

#### Algorithm
1. Choose a pivot.
2. Partition the array around the pivot.
3. Recurse into the relevant side based on the target index.
4. Return when the pivot lands at the desired position.

#### Code
```java
class Solution {
    private int[] nums;
    private int k;

    public int findKthLargest(int[] nums, int k) {
        this.nums = nums;
        this.k = nums.length - k;
        return quickSelect(0, nums.length - 1);
    }

    private int quickSelect(int left, int right) {
        if (left == right) {
            return nums[left];
        }

        int i = left - 1, j = right + 1;
        int pivot = nums[(left + right) >>> 1];

        while (i < j) {
            while (nums[++i] < pivot) {}
            while (nums[--j] > pivot) {}
            if (i < j) {
                int temp = nums[i];
                nums[i] = nums[j];
                nums[j] = temp;
            }
        }

        if (j < k) {
            return quickSelect(j + 1, right);
        }
        return quickSelect(left, j);
    }
}
```

#### Complexity
- Time Complexity: `O(n)` average
- Space Complexity: `O(1)`

### Sorting
#### Pattern
- Sorting

#### Intuition
Sorting the array makes the kth largest element appear at a known index. This is the simplest approach but not the most efficient when only one order statistic is needed.

#### Code
```java
class Solution {
    public int findKthLargest(int[] nums, int k) {
        Arrays.sort(nums);
        return nums[nums.length - k];
    }
}
```

#### Complexity
- Time Complexity: `O(n log n)`
- Space Complexity: `O(1)` or `O(n)` depending on implementation

## Approach Comparison
| Approach | Pattern | Time | Space | Pros | Cons |
| --- | --- | --- | --- | --- | --- |
| Min heap | Heap | `O(n log k)` | `O(k)` | Simple and reliable | Slightly slower than quickselect |
| Quickselect | Divide and Conquer | `O(n)` average | `O(1)` | Very efficient on average | Worst-case can degrade |
| Sorting | Sorting | `O(n log n)` | `O(1)`/`O(n)` | Easiest to understand | More work than necessary |

## Key Observations
- The kth largest element is the same as the $(n-k+1)$-th smallest element.
- A min-heap is ideal when only the top `k` values matter.
- Quickselect is often the best choice when average-case performance matters.

## Common Mistakes
- Confusing kth largest with kth distinct element.
- Forgetting that a min-heap keeps the smallest among the selected values.
- Off-by-one errors when converting between kth largest and index positions.

## Related Patterns
- Heap
- Quickselect
- Sorting

## Summary
- The optimal interview-friendly solution is the min-heap approach.
- The pattern is heap-based selection.
- Time complexity is `O(n log k)` and space complexity is `O(k)`.
- Interview takeaway: when you only need one order statistic, keeping a bounded heap is often the cleanest approach.
