# 334. Increasing Triplet Subsequence

## Problem Statement

Given an integer array nums, return true if there exists a triple of indices (i, j, k) such that:

- i < j < k
- nums[i] < nums[j] < nums[k]

If no such indices exist, return false.

## Example

- Input: nums = [1,2,3,4,5]
- Output: true

- Input: nums = [5,4,3,2,1]
- Output: false

- Input: nums = [2,1,5,0,4,6]
- Output: true

## Constraints

- 1 <= nums.length <= 5 * 10^5
- -2^31 <= nums[i] <= 2^31 - 1

## Intuition

We need to determine whether there exists any increasing subsequence of length 3.

A simple way is to track the smallest possible value for the first element and the smallest possible value for the second element of such a subsequence.

As we scan the array from left to right:

- keep the smallest value seen so far as first
- keep the best possible second value that can pair with first
- if we see a number greater than both, we have found the triplet

## Approach 1: Brute Force

### Idea

Check every possible triplet of indices (i, j, k) and return true if the values are strictly increasing.

This is simple but too slow for large inputs.

### Java Solution

```java
class Solution {
    public boolean increasingTriplet(int[] nums) {
        int n = nums.length;
        for (int i = 0; i < n; i++) {
            for (int j = i + 1; j < n; j++) {
                if (nums[j] > nums[i]) {
                    for (int k = j + 1; k < n; k++) {
                        if (nums[k] > nums[j]) {
                            return true;
                        }
                    }
                }
            }
        }
        return false;
    }
}
```

## Approach 2: Middle Fixing with Linear Scan

### Idea

For each middle index j, check whether there exists a smaller value before it and a larger value after it.

This improves the brute force but is still not optimal.

### Java Solution

```java
class Solution {
    public boolean increasingTriplet(int[] nums) {
        int n = nums.length;
        for (int j = 1; j < n - 1; j++) {
            boolean leftSmaller = false;
            boolean rightGreater = false;

            for (int i = 0; i < j; i++) {
                if (nums[i] < nums[j]) {
                    leftSmaller = true;
                    break;
                }
            }

            for (int k = j + 1; k < n; k++) {
                if (nums[k] > nums[j]) {
                    rightGreater = true;
                    break;
                }
            }

            if (leftSmaller && rightGreater) {
                return true;
            }
        }
        return false;
    }
}
```

## Approach 3: Greedy with Two Variables

### Idea

Maintain two variables:

- first: the smallest value that could be the first element of a valid pair
- second: the smallest value that could be the second element of a valid pair

For each num in nums:

- If num is smaller than or equal to first, update first.
- Else if num is smaller than or equal to second, update second.
- Else, we have found a value that is greater than both, so return true.

This works because first stores the best possible first element, and second stores the best possible second element after seeing a valid prefix.

## Java Solution

```java
class Solution {
    public boolean increasingTriplet(int[] nums) {
        int first = Integer.MAX_VALUE;
        int second = Integer.MAX_VALUE;

        for (int num : nums) {
            if (num <= first) {
                first = num;
            } else if (num <= second) {
                second = num;
            } else {
                return true;
            }
        }
        return false;
    }
}
```

## Why This Works

The algorithm maintains the best possible prefix structure for an increasing subsequence of length 2:

- first = minimum possible value at index i
- second = minimum possible value at index j such that there exists some i < j with nums[i] < nums[j]

When a number is larger than both first and second, it can serve as the third element of a valid triplet.

So if we ever encounter such a value, the answer is true.

## Complexity Analysis

- Time: O(n)
  - Each element is processed once.
- Space: O(1)
  - Only two integers are stored.

## Common Mistakes

- Using strict comparisons incorrectly, such as using < instead of <= in updates.
- Forgetting that the subsequence must be strictly increasing.
- Confusing the role of the second variable.

## Related Patterns

- Greedy scanning
- Prefix minimum tracking
- Subsequence detection

## Summary

This is a classic greedy problem. Instead of checking all triplets, we keep track of the smallest possible first and second values for an increasing subsequence and detect a valid third value in linear time.
