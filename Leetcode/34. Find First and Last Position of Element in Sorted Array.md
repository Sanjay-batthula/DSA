
# 34. Find First and Last Position of Element in Sorted Array

## Problem Statement

Given an array of integers `nums` sorted in non-decreasing order, find the starting and ending position of a given target value.

If target is not found in the array, return `[-1, -1]`.

You must write an algorithm with $O(\log n)$ runtime complexity.

---

## Sample Test Cases

| Input                          | Output   |
|--------------------------------|----------|
| nums = [5,7,7,8,8,10], target = 8 | [3,4]    |
| nums = [5,7,7,8,8,10], target = 6 | [-1,-1]  |
| nums = [], target = 0              | [-1,-1]  |

---

## Constraints

- $0 \leq \text{nums.length} \leq 10^5$
- $-10^9 \leq \text{nums}[i] \leq 10^9$
- `nums` is a non-decreasing array.
- $-10^9 \leq \text{target} \leq 10^9$

---

## Approaches

| Intuition | Approach | Time Complexity | Space Complexity |
|-----------|----------|-----------------|-----------------|
| Brute Force | Scan from left and right to find first and last occurrence | $O(n)$ | $O(1)$ |
| Binary Search (Double) | Use binary search to find left and right boundaries | $O(\log n)$ | $O(1)$ |
| HashMap | Store indices of each value, then lookup | $O(n)$ | $O(n)$ |
| Expansion from Found | Binary search for any occurrence, then expand | $O(\log n + k)$ | $O(1)$ |

---

## Code: Binary Search (Double)

```java
class Solution {
    public int[] searchRange(int[] nums, int target) {
        int left = findFirst(nums, target);
        int right = findFirst(nums, target + 1) - 1;
        if (left == nums.length || nums[left] != target) return new int[]{-1, -1};
        return new int[]{left, right};
    }

    private int findFirst(int[] nums, int x) {
        int left = 0, right = nums.length;
        while (left < right) {
            int mid = (left + right) >>> 1;
            if (nums[mid] >= x) right = mid;
            else left = mid + 1;
        }
        return left;
    }
}
```

## Other Approaches

### Brute Force
```java
class Solution {
    public int[] searchRange(int[] nums, int target) {
        int[] result = {-1, -1};
        for (int i = 0; i < nums.length; i++) {
            if (nums[i] == target) {
                result[0] = i;
                break;
            }
        }
        if (result[0] == -1) return result;
        for (int i = nums.length - 1; i >= 0; i--) {
            if (nums[i] == target) {
                result[1] = i;
                break;
            }
        }
        return result;
    }
}
```

### HashMap Frequency + First Occurrence Scan
```java
class Solution {
    public int[] searchRange(int[] nums, int target) {
        HashMap<Integer, ArrayList<Integer>> map = new HashMap<>();
        for (int i = 0; i < nums.length; i++) {
            map.computeIfAbsent(nums[i], k -> new ArrayList<>()).add(i);
        }
        if (!map.containsKey(target)) return new int[]{-1, -1};
        ArrayList<Integer> arr = map.get(target);
        return new int[]{arr.get(0), arr.get(arr.size() - 1)};
    }
}
```

### Expansion From Any Found Index (Optimized Hybrid)
```java
class Solution {
    public int[] searchRange(int[] nums, int target) {
        int idx = Arrays.binarySearch(nums, target);
        if (idx < 0) return new int[]{-1, -1};
        int l = idx, r = idx;
        while (l > 0 && nums[l - 1] == target) l--;
        while (r < nums.length - 1 && nums[r + 1] == target) r++;
        return new int[]{l, r};
    }
}
```

## Approach Comparison

| Approach | Time Complexity | Space Complexity | Notes |
|----------|-----------------|-----------------|-------|
| Brute Force | $O(n)$ | $O(1)$ | Simple, but not optimal |
| Binary Search (Double) | $O(\log n)$ | $O(1)$ | Optimal for sorted arrays |
| HashMap | $O(n)$ | $O(n)$ | Overkill for this problem |
| Expansion from Found | $O(\log n + k)$ | $O(1)$ | $k$ is number of target occurrences |

---

## Summary

- Use binary search to efficiently find the left and right boundaries of the target value in a sorted array.
- Always check for edge cases: empty array, target not present.
- Brute force and HashMap approaches are less efficient and not recommended for large inputs.
