# 38. Count and Say

## Problem Statement
Given a positive integer n, generate the nth element of the count-and-say sequence. The sequence starts with "1", and each next term is formed by reading the previous term as groups of consecutive identical digits and replacing each group with the count followed by the digit.

## Sample Test Cases
| Input | Output | Explanation |
| --- | --- | --- |
| `n = 1` | `"1"` | Base case |
| `n = 4` | `"1211"` | `"1" -> "11" -> "21" -> "1211"` |

## Constraints
- `1 <= n <= 30`

## Approaches
| Approach | Pattern | Time Complexity | Space Complexity |
| --- | --- | --- | --- |
| Iterative run-length encoding | Run-Length Encoding / Two Pointers | `O(L_n)` | `O(L_n)` |

## Code
### Pattern
- Run-Length Encoding (RLE)
- Two Pointers

### Intuition
The sequence is built by scanning the previous string and grouping consecutive identical characters. Each group contributes a compressed description of the form "count + digit". This is exactly the same idea as run-length encoding.

The main challenge is to preserve the boundaries between groups. A pointer can move across the string until the character changes, and then the code records the group length and the digit. Repeating this process for each iteration produces the next term.

### Algorithm
1. Start with the base string `"1"`.
2. Repeat the following process `n - 1` times:
   1. Scan the current string from left to right.
   2. For each maximal block of identical characters, count its length and append the count followed by the character.
   3. Replace the current string with the newly built string.
3. Return the final string.

### Code
```java
class Solution {
    public String countAndSay(int n) {
        String s = "1";
        while (--n > 0) {
            StringBuilder t = new StringBuilder();
            for (int i = 0; i < s.length();) {
                int j = i;
                while (j < s.length() && s.charAt(j) == s.charAt(i)) {
                    ++j;
                }
                t.append((j - i) + "");
                t.append(s.charAt(i));
                i = j;
            }
            s = t.toString();
        }
        return s;
    }
}
```

### Complexity
- Time Complexity: `O(L_n)`
- Space Complexity: `O(L_n)`

| Iterative RLE | Run-Length Encoding / Two Pointers | `O(L_n)` | `O(L_n)` | Simple and directly follows the definition | Rebuilds a new string at each step |

## Key Observations
- Each term is generated from the previous term by grouping consecutive equal digits.
- The core operation is identifying maximal runs, not arbitrary substring matching.
- Every run contributes exactly one encoded piece: `count + digit`.

## Common Mistakes
- Off-by-one errors when handling loop boundaries.
- Forgetting to reset the scan after each group.
- Appending the wrong character when building the next term.
- Confusing the count and the digit order.

## Related Patterns
- Run-Length Encoding
- String Simulation
- Two Pointers

## Summary
- The optimal solution builds each term by scanning the previous term and compressing each run of identical digits.
- The pattern is Run-Length Encoding with a simple left-to-right scan.
- Time complexity is `O(L_n)`, and space complexity is `O(L_n)`, where $L_n$ is the length of the nth term.
- Interview takeaway: this problem is a clean example of turning a recursive definition into an iterative string-building approach.
