# 386. Lexicographical Numbers

## Problem Statement

Given an integer `n`, return the numbers in the range `[1, n]` in lexicographical order.

The required algorithm must run in `O(n)` time and use `O(1)` extra space, excluding the space needed for the returned list.

## Sample Test Cases

### Example 1

```text
Input: n = 13
Output: [1,10,11,12,13,2,3,4,5,6,7,8,9]
```

### Example 2

```text
Input: n = 2
Output: [1,2]
```

## Brute Force: String Sorting

| Section | Details |
|---|---|
| **Intuition** | Generate every number from `1` to `n`, then order their decimal representations as strings. |
| **Approach** | Add all integers to a list and sort them using `String.compareTo` on each pair of values. |
| **Time Complexity** | `O(n log n)` comparisons; each comparison may take up to `O(log n)` character work for general `n`. |
| **Space Complexity** | `O(n)` for the result list and sorting storage. |

This approach produces lexicographical order, but it does not meet the problem's required `O(n)` time and `O(1)` extra-space bounds.

```java
class Solution {
    public List<Integer> lexicalOrder(int n) {
        List<Integer> ans = new  ArrayList<>();
        for(int i=1;i<=n;i++) ans.add(i);
        Collections.sort(ans, (a,b) -> {
            String s1 = Integer.toString(a);
            String s2 = Integer.toString(b);
            return s1.compareTo(s2);
        });
    return ans;
    }
}
```

## Lexicographical DFS Traversal ✅

| Section | Details |
|---|---|
| **Intuition** | Numbers in lexicographical order can be traversed like a prefix tree: visit a number's children by appending digits before moving to the next sibling. |
| **Approach** | Start at `1`. Append a zero when the resulting number is at most `n`; otherwise move to the next number, backing up through trailing `9`s or values beyond `n` as needed. Repeat for exactly `n` values. |
| **Time Complexity** | `O(n)`; the total work spent moving up and across the implicit prefix tree is linear. |
| **Space Complexity** | `O(1)` auxiliary space, excluding the `O(n)` returned list. |

```java
class Solution {
    public List<Integer> lexicalOrder(int n) {
        List<Integer> res = new ArrayList<>();
        int curr = 1;
        for (int i = 0; i < n; i++) {
            res.add(curr);
            if (curr * 10 <= n) {
                curr *= 10;
            } else {
                while (curr % 10 == 9 || curr + 1 > n) {
                    curr /= 10;
                }
                curr++;
            }
        }
        return res;
    }
}
```

## Iterative DFS with a Stack (Python)

| Section | Details |
|---|---|
| **Intuition** | Treat each number as a prefix and its possible next digits as children. A depth-first traversal visits prefixes in lexicographical order. |
| **Approach** | Pop the next number and append it to the result. Push its next sibling first, then its first child; the child is processed first, preserving depth-first lexicographical order. |
| **Time Complexity** | `O(n)`; each value is visited once and at most ten children are checked. |
| **Space Complexity** | `O(log n)` auxiliary space for the pending DFS stack, excluding the `O(n)` result list. |

This is a different traversal implementation from the constant-space arithmetic walk above. Keeping pending siblings on the stack uses `O(log n)` auxiliary space, so it does not meet the problem's `O(1)` extra-space requirement.

```python
class Solution:
    def lexicalOrder(self, n: int) -> list[int]:
        result = []
        stack = [1]
        while stack:
            current = stack.pop()
            result.append(current)
            sibling = current + 1
            if current % 10 < 9 and sibling <= n:
                stack.append(sibling)
            child = current * 10
            if child <= n:
                stack.append(child)
        return result
```

## Approach Comparison

| Approach | Time Complexity | Extra Space (excluding result) | Meets Required Bounds? | Notes |
|---|---|---|---|---|
| String sorting | `O(n log n)` comparisons, with up to `O(log n)` character work per comparison | `O(n)` | No | Straightforward; generates the values and sorts their string forms. |
| Lexicographical traversal | `O(n)` | `O(1)` | Yes | Walks the implicit prefix tree without sorting. |
| Iterative DFS with a stack | `O(n)` | `O(log n)` | No | Also walks the prefix tree, storing pending children explicitly. |

## Summary

- The prefix-tree traversal meets the required `O(n)` time and `O(1)` auxiliary-space bounds.
- Appending a zero visits a deeper prefix; incrementing or backing up moves to the next lexicographical number.
- An explicit DFS stack also yields lexicographical order, but uses `O(log n)` auxiliary space.
- String sorting also produces the requested order, but requires sorting time and additional storage.
