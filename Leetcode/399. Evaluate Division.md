# 399. Evaluate Division

## Problem Statement

Given equations of the form `A / B = value`, answer queries of the form `C / D`. Return `-1.0` if either variable is undefined or the quotient cannot be determined from the equations.

The input is valid, equations are consistent, and query evaluation does not involve division by zero. Variables are lowercase letters and digits. There are between 1 and 20 equations and between 1 and 20 queries; each variable name has length 1 to 5, and each equation value is greater than `0.0` and at most `20.0`.

## Sample Test Cases

### Example 1

```text
Input:
equations = [["a","b"],["b","c"]]
values = [2.0,3.0]
queries = [["a","c"],["b","a"],["a","e"],["a","a"],["x","x"]]
Output: [6.0,0.5,-1.0,1.0,-1.0]
```

The equations imply `a / c = 2.0 * 3.0 = 6.0`. Variable `e` is undefined, and `x` does not appear in any equation.

### Example 2

```text
Input:
equations = [["a","b"],["b","c"],["bc","cd"]]
values = [1.5,2.5,5.0]
queries = [["a","c"],["c","b"],["bc","cd"],["cd","bc"]]
Output: [3.75,0.4,5.0,0.2]
```

### Example 3

```text
Input:
equations = [["a","b"]]
values = [0.5]
queries = [["a","b"],["b","a"],["a","c"],["x","y"]]
Output: [0.5,2.0,-1.0,-1.0]
```

## Weighted Union-Find (Disjoint Set Union with Ratios) ✅

| Section | Details |
|---|---|
| **Intuition** | Variables connected by equations belong to the same set. Store each variable's ratio to its parent so that, after finding the common root, the ratio between two variables can be calculated. |
| **Approach** | Initialize each variable as its own parent with ratio `1.0`. For each equation `a / b = value`, find both roots; if they differ, attach `a`'s root under `b`'s root and set the attached root's weight to preserve the equation. For a query, return `-1.0` if either variable is unknown or their roots differ; otherwise divide their weights to the root. `find` compresses paths and updates weights. |
| **Time Complexity** | `O((E + Q)V)` worst case for this implementation, where `E` is the number of equations, `Q` is the number of queries, and `V` is the number of distinct variables. Path compression improves repeated finds, but this code does not use union by rank or size to guarantee the usual near-constant amortized bound. |
| **Space Complexity** | `O(V)` for the parent and weight maps and the worst-case recursive `find` call stack, excluding the `O(Q)` result array. |

```java
class Solution {
    private Map<String, String> p;
    private Map<String, Double> w;

    public double[] calcEquation(
        List<List<String>> equations, double[] values, List<List<String>> queries) {
        int n = equations.size();
        p = new HashMap<>();
        w = new HashMap<>();
        for (List<String> e : equations) {
            p.put(e.get(0), e.get(0));
            p.put(e.get(1), e.get(1));
            w.put(e.get(0), 1.0);
            w.put(e.get(1), 1.0);
        }
        for (int i = 0; i < n; ++i) {
            List<String> e = equations.get(i);
            String a = e.get(0), b = e.get(1);
            String pa = find(a), pb = find(b);
            if (Objects.equals(pa, pb)) {
                continue;
            }
            p.put(pa, pb);
            w.put(pa, w.get(b) * values[i] / w.get(a));
        }
        int m = queries.size();
        double[] ans = new double[m];
        for (int i = 0; i < m; ++i) {
            String c = queries.get(i).get(0), d = queries.get(i).get(1);
            ans[i] = !p.containsKey(c) || !p.containsKey(d) || !Objects.equals(find(c), find(d))
                ? -1.0
                : w.get(c) / w.get(d);
        }
        return ans;
    }

    private String find(String x) {
        if (!Objects.equals(p.get(x), x)) {
            String origin = p.get(x);
            p.put(x, find(p.get(x)));
            w.put(x, w.get(x) * w.get(origin));
        }
        return p.get(x);
    }
}
```

## Summary

- The weighted union-find stores each variable's ratio to its parent and compresses paths while preserving the ratio to the root.
- Variables yield a determinate quotient only when both are known and share a root; divide their root-relative weights to answer the query.
- This implementation uses path compression but no union-by-rank or size, so its worst-case find cost is linear in the number of variables.
