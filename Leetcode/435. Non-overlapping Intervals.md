# 435. Non-overlapping Intervals

## Problem Statement

Given an array of intervals, return the minimum number to remove so the remaining intervals do not overlap. Intervals that touch at an endpoint, such as `[1,2]` and `[2,3]`, are non-overlapping.

There is at least one interval, each interval has two endpoints, and `-5 * 10^4 <= start < end <= 5 * 10^4`.

## Sample Test Cases

### Example 1

```text
Input: intervals = [[1,2],[2,3],[3,4],[1,3]]
Output: 1
```

Remove `[1,3]`; the other intervals do not overlap.

### Example 2

```text
Input: intervals = [[1,2],[1,2],[1,2]]
Output: 2
```

### Example 3

```text
Input: intervals = [[1,2],[2,3]]
Output: 0
```

## Greedy: Earliest Finishing Interval ✅

| Section | Details |
|---|---|
| **Intuition** | Keeping an interval that ends earlier leaves as much room as possible for the remaining intervals. |
| **Approach** | Sort intervals by end time. Keep the first interval, then keep each later interval whose start is at least the end of the last kept interval. Remove all intervals not kept. |
| **Time Complexity** | `O(n log n)` for sorting, followed by an `O(n)` scan. |
| **Space Complexity** | `O(log n)` auxiliary space for the sort in typical Java implementations; the sort may modify the input array. |

```java
class Solution {
    public int eraseOverlapIntervals(int[][] intervals) {
        int len = intervals.length;
        if(len == 0) return 0;
        Arrays.sort(intervals, (a, b)->{
            return a[1] - b[1];
        });
        int end = intervals[0][1];
        int count = 1;
        for(int i = 1; i < len; i++){
            if(intervals[i][0] >= end){
                end = intervals[i][1];
                count++;
            }
        }
        return len - count;
    }
}
```

## Dynamic Programming: Longest Non-Overlapping Subsequence

| Section | Details |
|---|---|
| **Intuition** | The minimum removals equal the number of intervals minus the largest subset that can be kept without overlap. |
| **Approach** | Sort by start time. For each interval, compute the longest valid sequence ending there by checking all earlier intervals that finish no later than its start. Return the total count minus the longest sequence found. |
| **Time Complexity** | `O(n^2)` after sorting. |
| **Space Complexity** | `O(n)` for the DP array. |

This approach is correct but can be too slow for large inputs (`n` can be `10^5`).

```java
class Solution {
    public int eraseOverlapIntervals(int[][] intervals) {
        int n = intervals.length;
        Arrays.sort(intervals, (a, b) -> a[0] - b[0]);
        int[] dp = new int[n];
        Arrays.fill(dp, 1);
        int max = 1;
        for (int i = 1; i < n; i++) {
            for (int j = 0; j < i; j++) {
                if (intervals[j][1] <= intervals[i][0]) {
                    dp[i] = Math.max(dp[i], dp[j] + 1);
                }
            }
            max = Math.max(max, dp[i]);
        }
        return n - max;
    }
}
```

## Approach Comparison

| Approach | Time Complexity | Space Complexity | Notes |
|---|---|---|---|
| Greedy by end time | `O(n log n)` | `O(log n)` auxiliary, typical Java sort | Preferred; selects a maximum-size compatible set in one scan after sorting. |
| Dynamic programming | `O(n^2)` | `O(n)` | Computes the longest compatible sequence; may time out for the maximum input size. |

## Summary

- Minimizing removals is equivalent to maximizing the number of non-overlapping intervals kept.
- Greedily keeping the interval with the earliest end gives an `O(n log n)` solution.
- The DP solution expresses the same goal as a longest compatible subsequence, but its quadratic time is impractical at the stated limit.
