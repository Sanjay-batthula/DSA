# 602. Friend Requests II: Who Has the Most Friends

## Problem Statement

Given accepted friend requests, find the ID of the person with the most friends and their friend count. The test data guarantees a unique person with the maximum count.

The `(requester_id, accepter_id)` pair is unique in `RequestAccepted`.

## Sample Test Case

```text
RequestAccepted:
+--------------+-------------+-------------+
| requester_id | accepter_id | accept_date |
+--------------+-------------+-------------+
| 1            | 2           | 2016/06/03  |
| 1            | 3           | 2016/06/08  |
| 2            | 3           | 2016/06/08  |
| 3            | 4           | 2016/06/09  |
+--------------+-------------+-------------+
Output:
+----+-----+
| id | num |
+----+-----+
| 3  | 3   |
+----+-----+
```

Person `3` appears in accepted requests with people `1`, `2`, and `4`, giving them three friends.

## Union All + Group By ✅

```sql
SELECT id, COUNT(*) AS num
FROM (
    SELECT requester_id AS id FROM RequestAccepted
    UNION ALL
    SELECT accepter_id AS id FROM RequestAccepted
) AS all_friends
GROUP BY id
ORDER BY num DESC
LIMIT 1;
```

## Explanation

| Section | Details |
|---|---|
| **Intuition** | A person can appear as either the requester or the accepter, so count both roles as friend connections. |
| **Approach** | `UNION ALL` combines both ID columns while retaining every occurrence. `GROUP BY id` counts each person's appearances, and sorting by `num` with `LIMIT 1` returns the unique maximum guaranteed by the problem. |
| **Key Concepts** | `UNION ALL`, `GROUP BY`, `COUNT()`, `ORDER BY`, `LIMIT` |

## Alternative Approach: CTE + `RANK()`

```sql
WITH friend_count AS (
    SELECT id, COUNT(*) AS num
    FROM (
        SELECT requester_id AS id FROM RequestAccepted
        UNION ALL
        SELECT accepter_id AS id FROM RequestAccepted
    ) t
    GROUP BY id
)
SELECT id, num
FROM (
    SELECT *,
           RANK() OVER (ORDER BY num DESC) AS rnk
    FROM friend_count
) t
WHERE rnk = 1;
```

This query also returns all people tied for the maximum, addressing the follow-up where the maximum may not be unique.

## Summary

- Count both requester and accepter appearances to get each person's number of friends.
- The `LIMIT 1` query is appropriate under the problem's unique-maximum guarantee.
- Use `RANK()` when all people tied for the maximum should be returned.
