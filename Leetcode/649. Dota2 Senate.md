# 649. Dota2 Senate

## Problem Statement

Given a string `senate` containing `'R'` for Radiant and `'D'` for Dire senators in voting order, predict which party wins when senators optimally ban opposing senators' voting rights. Return `"Radiant"` or `"Dire"`.

The string length is between 1 and `10^4`.

## Sample Test Cases

### Example 1

```text
Input: senate = "RD"
Output: "Radiant"
```

The first Radiant senator bans the Dire senator, leaving Radiant to win.

### Example 2

```text
Input: senate = "RDD"
Output: "Dire"
```

The Radiant senator bans one Dire senator, then the remaining Dire senator bans Radiant.

## Brute Force Simulation

| Section | Details |
|---|---|
| **Intuition** | Simulate senators in order and have each active senator ban the next active opposing senator. |
| **Approach** | Track banned positions and remaining counts. For each active senator, scan circularly to find the next active senator of the opposing party, ban them, and stop when one party has no senators left. |
| **Time Complexity** | `O(n^2)` worst case: each of up to `n` bans may scan up to `n` positions. |
| **Space Complexity** | `O(n)` for the character array and banned flags. |

```java
class Solution {
    public String predictPartyVictory(String senate) {
        int n = senate.length();
        char[] arr = senate.toCharArray();
        boolean[] banned = new boolean[n];
        int r = 0, d = 0;
        for (char c : arr) {
            if (c == 'R') r++;
            else d++;
        }
        while (r > 0 && d > 0) {
            for (int i = 0; i < n; i++) {
                if (banned[i]) continue;
                char cur = arr[i];
                int j = (i + 1) % n;
                while (j != i && (banned[j] || arr[j] == cur)) j = (j + 1) % n;
                if (j == i) {
                    return cur == 'R' ? "Radiant" : "Dire";
                } else {
                    banned[j] = true;
                    if (arr[j] == 'R') r--;
                    else d--;
                }
                if (r == 0) return "Dire";
                if (d == 0) return "Radiant";
            }
        }
        return r > 0 ? "Radiant" : "Dire";
    }
}
```

## Greedy: Two Queues ✅

| Section | Details |
|---|---|
| **Intuition** | The next senator to act is the earliest remaining senator in the original order. After acting, that senator returns in a later round. |
| **Approach** | Store each party's indices in separate queues. Compare their front indices: the earlier senator bans the opposing senator and is re-enqueued at `index + n`, placing them after the current round. The party whose queue remains non-empty wins. |
| **Time Complexity** | `O(n)`, since each senator is re-enqueued only when they act, and each action removes one opposing senator. |
| **Space Complexity** | `O(n)` for the two queues. |

```java
import java.util.LinkedList;
import java.util.Queue;

class Solution {
    public String predictPartyVictory(String senate) {
        Queue<Integer> radiant = new LinkedList<>();
        Queue<Integer> dire = new LinkedList<>();

        for (int i = 0; i < senate.length(); i++) {
            if (senate.charAt(i) == 'R') {
                radiant.add(i);
            } else {
                dire.add(i);
            }
        }

        while (!radiant.isEmpty() && !dire.isEmpty()) {
            int rIndex = radiant.poll();
            int dIndex = dire.poll();

            if (rIndex < dIndex) {
                radiant.add(rIndex + senate.length());
            } else {
                dire.add(dIndex + senate.length());
            }
        }

        return radiant.isEmpty() ? "Dire" : "Radiant";
    }
}
```

## Greedy with Count Tracking

| Section | Details |
|---|---|
| **Intuition** | A pending ban can be carried forward to remove an opposing senator when their turn arrives. |
| **Approach** | Track banned senators and remaining party counts. `banR` and `banD` store pending bans against the corresponding parties. Scan in order, consume a pending ban to skip a senator or add a ban against the opposing party. Repeat rounds until one party is eliminated. |
| **Time Complexity** | `O(n^2)` worst case, as the code may scan the full senate string across multiple rounds. |
| **Space Complexity** | `O(n)` for the banned flags. |

```java
class Solution {
    public String predictPartyVictory(String senate) {
        int n = senate.length();
        boolean[] banned = new boolean[n];
        int r = 0, d = 0;
        for (char c : senate.toCharArray()) {
            if (c == 'R') r++;
            else d++;
        }
        int banR = 0, banD = 0;
        while (r > 0 && d > 0) {
            for (int i = 0; i < n; i++) {
                if (banned[i]) continue;
                if (senate.charAt(i) == 'R') {
                    if (banR > 0) { banned[i] = true; banR--; r--; }
                    else banD++;
                } else {
                    if (banD > 0) { banned[i] = true; banD--; d--; }
                    else banR++;
                }
                if (r == 0 || d == 0) break;
            }
        }
        return r > 0 ? "Radiant" : "Dire";
    }
}
```

## Approach Comparison

| Approach | Time Complexity | Space Complexity | Notes |
|---|---|---|---|
| Brute force simulation | `O(n^2)` | `O(n)` | Explicitly scans for the next opposing senator. |
| Two queues | `O(n)` | `O(n)` | Preferred; queue order directly simulates turns across rounds. |
| Greedy with count tracking | `O(n^2)` | `O(n)` | Carries pending bans through repeated scans of the original order. |

## Summary

- Each senator bans the next available opposing senator in cyclic order.
- Two queues represent the next turn for each party; adding `n` moves a surviving senator into the next round.
- The queue approach avoids repeated full-array scans and runs in `O(n)` time.
