# 🧠 Problem: 4. Median of Two Sorted Arrays

---

## 🚀 Intuition
We're given two **sorted arrays**, and we need to find the **median** of the combined array **without actually merging** them.

Your first thought might be to merge them and then just pick the middle elements.  
But that takes `O(m + n)` time and `O(m + n)` space — and we can do better with a divide-and-conquer idea.

---

## 🧩 Approach
The trick here is to **find the K-th smallest element** in the union of two sorted arrays — without merging them.

### How it works:
- To find the median:
  - If total length is odd → find `(m + n + 1) / 2`
  - If even → average of `(m + n + 1) / 2` and `(m + n + 2) / 2`
- Use a recursive function `f(i, j, k)`:
  - Finds the k-th smallest element starting from `i` in `nums1` and `j` in `nums2`.
  - At each step, eliminate `k/2` elements from one of the arrays based on value comparison.

This is a **modified binary search** over the two arrays.

---

## ⏱️ Complexity

- **Time Complexity:**  
  $$O(\log (m + n))$$  
  Because we cut `k` in half on every recursive call.

- **Space Complexity:**  
  $$O(\log (m + n))$$ due to recursion stack.

---

# 1. Brute Force Approach — The Basic Idea
💡 Concept:

Merge both arrays, sort the merged one, and then pick the median.

⚙️ Steps:

Combine nums1 and nums2 into a new array.

Sort it (though they’re already sorted individually).

If total length L is odd → return middle element.
If even → return average of the two middle elements.

⏱️ Time Complexity:

Merging: O(m + n)

Sorting (if not merged cleverly): O((m + n) log(m + n))

With two-pointer merge (since sorted): O(m + n)

👉 Brute force complexity: O(m + n)
👉 Space: O(m + n)


## Brute Force Code
```
class Solution {
    public double findMedianSortedArrays(int[] nums1, int[] nums2) {
        int m = nums1.length, n = nums2.length;
        int[] merged = new int[m + n];
        int i = 0, j = 0, k = 0;
        while (i < m && j < n) {
            if (nums1[i] < nums2[j]) merged[k++] = nums1[i++];
            else merged[k++] = nums2[j++];
        }
        while (i < m) merged[k++] = nums1[i++];
        while (j < n) merged[k++] = nums2[j++];

        int len = m + n;
        if (len % 2 == 1) return merged[len / 2];
        else return (merged[len / 2 - 1] + merged[len / 2]) / 2.0;
    }
}
```


# ⚡ 2. The Recursive Approach

🚀 Type:

This is an Optimized Binary Search on k-th element approach.
Basically, instead of merging, we find the k-th smallest element recursively.

🔍 How it Works:

The function f(i, j, k) returns the k-th smallest element starting from nums1[i:] and nums2[j:].

At every call, we:

Compare the k/2th elements of both subarrays.

Discard the half that cannot contain the k-th element.

This cuts down the search space by half each time — giving O(log (m + n)) complexity.

## Pseudo code
```java
class Solution {
    private int m;
    private int n;
    private int[] nums1;
    private int[] nums2;

    public double findMedianSortedArrays(int[] nums1, int[] nums2) {
        m = nums1.length;
        n = nums2.length;
        this.nums1 = nums1;
        this.nums2 = nums2;
        int a = f(0, 0, (m + n + 1) / 2);
        int b = f(0, 0, (m + n + 2) / 2);
        return (a + b) / 2.0;
    }

    private int f(int i, int j, int k) {
        if (i >= m) return nums2[j + k - 1];
        if (j >= n) return nums1[i + k - 1];
        if (k == 1) return Math.min(nums1[i], nums2[j]);

        int p = k / 2;
        int x = i + p - 1 < m ? nums1[i + p - 1] : Integer.MAX_VALUE;
        int y = j + p - 1 < n ? nums2[j + p - 1] : Integer.MAX_VALUE;

        return x < y ? f(i + p, j, k - p) : f(i, j + p, k - p);
    }
}
```
🧩 What’s Happening:

It finds the (m+n+1)/2-th and (m+n+2)/2-th smallest elements.

The average of these two gives the median.

Recursion keeps reducing k (the rank of the element we’re searching for).

⚙️ Time Complexity:

O(log (m + n))
(because each step drops half of one array)

🧠 Type:

👉 Divide and Conquer / Binary Search on k-th smallest element.




# 3. Binary Search Partition Method
This is the official editorial approach.

🔍 Idea:

Partition both arrays such that:

Left part has exactly half of the total elements.

Every element in the left ≤ every element in the right.

We do binary search on the smaller array to find that perfect partition.

⚙️ Steps:

1. Assume nums1 is smaller.

2. Binary search on its index i, and find corresponding index j in nums2.

3. Check partition conditions:

```
maxLeft1 <= minRight2
maxLeft2 <= minRight1
```
4. If satisfied → compute median.

5. Else move search left or right.

⏱️ Time:

O(log(min(m, n)))
Space: O(1)

```
class Solution {
    public double findMedianSortedArrays(int[] nums1, int[] nums2) {
        if (nums1.length > nums2.length) return findMedianSortedArrays(nums2, nums1);
        int m = nums1.length, n = nums2.length;
        int left = 0, right = m;
        while (left <= right) {
            int i = (left + right) / 2;
            int j = (m + n + 1) / 2 - i;
            int maxLeft1 = (i == 0) ? Integer.MIN_VALUE : nums1[i - 1];
            int minRight1 = (i == m) ? Integer.MAX_VALUE : nums1[i];
            int maxLeft2 = (j == 0) ? Integer.MIN_VALUE : nums2[j - 1];
            int minRight2 = (j == n) ? Integer.MAX_VALUE : nums2[j];
            if (maxLeft1 <= minRight2 && maxLeft2 <= minRight1) {
                if ((m + n) % 2 == 0)
                    return (Math.max(maxLeft1, maxLeft2) + Math.min(minRight1, minRight2)) / 2.0;
                else
                    return Math.max(maxLeft1, maxLeft2);
            } else if (maxLeft1 > minRight2) right = i - 1;
            else left = i + 1;
        }
        return 0.0;
    }
}
```
